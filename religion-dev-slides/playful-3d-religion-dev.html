기억엔진 원칙

모든 claim은 출처를 가진다

1LLM 답변을 “그럴듯함”이 아니라 원문 근거로 검증한다.

skin HTML/CSSgallery, merian, buylow 같은 디자인 변형. DOM hook과 capability는 유지.

Cloudflare 실제 운영

Cloudflare는 public edge와 tunnel 라우터다

브라우저는 `psykey.ai.kr`를 치지만, Cloudflare CNAME/tunnel이 EC2 connector origin으로 흘려보낸다.

Named tunnel: lawkey-prod
Connector origin IP: 43.200.191.87
네임서버 등록법

새 도메인 기준

1Cloudflare에 site 추가 → Cloudflare가 두 개의 nameserver를 준다.
2도메인 등록기관에서 기존 NS를 Cloudflare NS로 교체한다.
3Cloudflare DNS에 `A/CNAME` 또는 tunnel CNAME을 만들고 proxied를 켠다.
4`curl /api/health`, browser submit, source-window까지 확인한 뒤 앱 origin에 stamp한다.

우리 기준의 원칙

quick tunnel URL은 시연용이다. APK, 외부 공유, 장기 운영은 `lawkey.ai.kr`/`psykey.ai.kr` 같은 durable domain으로만 찍는다. 터널 URL이 죽어 앱이 하얗게 뜬 실패 기록이 있다.

자동화 루프

describe→patch→restart→health→browser proof

AI는 credentials를 출력하지 않고, 상태 조회·적용·검증 로그만 남긴다.

실패 방지

1비용/권한은 추측하지 않는다. AWS credentials 없으면 Cost Explorer를 봤다고 말하지 않는다.
2Cloudflare cache/service worker 문제는 purge와 headers 확인까지 한다.
3public Python fetch가 403이어도 실제 browser path가 성공할 수 있으므로 둘을 구분한다.
서비스워커와 캐시

사이트가 고쳐졌는데 폰에서 안 바뀌는 이유

실제 PsyKey 이슈에서 Cloudflare가 예전 `sw.js`를 HIT로 반환해 새 UI가 가려졌다.

//index.html/sw.jspurge

규약

디자인/라우트 교체 후에는 SW cache key를 bump하고, Cloudflare purge와 fresh browser 확인을 같이 한다. “내 로컬에서는 바뀜”은 배포 성공이 아니다.

실전 사고 대응

502

Cloudflare 502가 보이면 먼저 origin을 본다. 실제 기록: `psykey.ai.kr/api/{islam,catholic,tcm}/jobs` 502 원인은 shared origin `:25565` 사망이었다.

하얀 앱

quick tunnel origin으로 stamp한 APK는 터널 만료 시 초기 HTML을 못 받아 하얗게 죽는다. 해결은 production domain 또는 embedded frontend다.

옛 화면

Cloudflare/SW/WebView cache가 같은 origin의 예전 HTML을 재사용할 수 있다. purge, cache-busting, fresh install/browser profile로 확인한다.

비용

AWS 비용은 Cost Explorer 권한 없이 추측하지 않는다. 메모리 기준 t3a.large+100GB EBS+상시 구동은 큰 고정비 후보였다.
